# Run and deploy your AI Studio app

This contains everything you need to run your app locally.

View your app in AI Studio: https://ai.studio/apps/e06960ed-7d2c-45bc-be51-1ff696f59058

## Run Locally

**Prerequisites:**  Node.js


1. Install dependencies:
   `npm install`
2. Set the `GEMINI_API_KEY` in [.env.local](.env.local) to your Gemini API key
3. Run the app:
   `npm run dev`

## OneStock design system

The UI follows the OneStock product design system (back-office):

- `styles/onestock.css`: design tokens (colours, spacing, radii, Roboto type scale) and component styles.
- `components/os/`: React versions of the `Os*` components used here (OsIcon, OsButton, OsBadge, OsTag, OsCheckbox, OsSwitch, OsSegmentedControl, OsAlert, OsStepper).
- `components/Layout.tsx`: content area only. The app runs as an extension inside the OneStock back-office, which already provides `OsSideMenu` and `OsNavBar`.
- `public/icons/`: official OneStock icons. Do not substitute another icon set.

## Two data sources: static and dynamic

The data source is chosen in the **Settings** tab (*Data source*) and saved per environment + site ID:

| | Static | Dynamic |
|---|---|---|
| Orders, items, suppliers | Sample data (`constants.tsx`) | OneStock API of the environment |
| Settings and prices | Browser storage | Vercel Postgres database, per environment + site ID |

`VITE_DATA_MODE=dynamic` only sets the default source of a site that has none saved (static otherwise).

### Tabs

- **Strategies**: wave strategies and the consolidation simulation. *Cheapest purchase price* takes the lowest unit price per SKU; *Price and Franco optimisation* then moves SKUs to other suppliers (dearer unit price, but franco reached or lower shipping fees) while the total purchase cost including shipping fees decreases, and shows the saving. Saved per environment + site ID in the database (dynamic) or in the browser (static). Each condition of the execution scenario can be removed and added back. The order creation date condition is relative to the run day (e.g. D-7 to D-1, recomputed at each run) or between fixed dates; lines without a date are left out when it is set. Other order conditions: sales channel (list from `GET /v3/sales_channels`, plus channels found in the orders), order type (values found in the loaded orders), customer (name or email contains) and item (SKU or name contains), several values separated by commas.
- **Supplier orders**: purchase orders created by *Launch*, one per supplier (suppliers blocked below their franco are left out), with their lines, the orders they supply, the shipping fee and an Excel export; filters by supplier, item, customer order and creation date. When an *order line status after launch* is set in the settings, Launch also moves each order line to that status in OneStock (`PATCH /v3/line_item_groups/{id}` with `line_item_group: { from, to }`) and the tab shows the lines that failed.
- **Supplier prices**: suppliers are the supplier stock points of OneStock plus suppliers entered in the app (*Add supplier*, or created by the Excel import when the file names an unknown supplier ID, with its `supplier_name`). Purchase prices per supplier and item, with quantity tiers (degressive prices), the franco of each supplier and the shipping fee it charges when the franco is not reached: a fixed amount per order, an amount per kg (with the item weights) or an amount per unit ordered. Entry by hand or Excel import (`weight_kg` column in *Prices*, `shipping_mode` / `shipping_amount` in *Franco*); *Download template* gives an example file (also in `public/templates/supplier-prices-example.xlsx`, regenerated by `npm run template`).
- **Settings** (hidden): the tab after *Supplier prices* is invisible until the mouse hovers it; `?settings` in the URL opens it directly. Data source (static or dynamic); environment connection: environment, site ID, OneStock API user and password (a token is requested with `POST /login`); order line statuses to retrieve, the order line status after launch, the `endpoint_type` classification of supplier stock points, and the purge of supplier orders (created before a date, or all; settings key required).

### Language

The interface follows the `lang` URL parameter sent by OneStock (browser language outside OneStock); `locale` sets the date and number formats. English and French are available (`services/i18n.fr.ts`); another language falls back to English. English texts are the keys: add a language with a dictionary file like `i18n.fr.ts` registered in `services/i18n.ts`. `npm run i18n:check` lists the texts without a French translation. Messages returned by the OneStock API and the server stay in English.

### OneStock UI extension context

OneStock loads the extension in an iframe with the URL parameters `extension_id`, `user_id`, `site_id`, `lang`, `timezone`, `locale`, `parent_url`, `injection_point_path` and `host_app`.

- An inline script in `index.html` posts `{ type: "extension_ready" }` to the origin of `parent_url` as soon as the page loads (OneStock fails the extension after 20 s without it, or when the origin differs from the configured `url` / `test_url`).
- The host replies `{ type: "onestock_data", data: { api_url, extension_signature, ... } }`; the message is accepted only from `window.parent` with the `parent_url` origin.
- `services/context.ts` takes the site ID from `site_id` and the environment from `api_url` (`https://c00.api.qualif.onestock-retail.com` → `qualif`, `https://c00.api.onestock-retail.com` → `prod`).
- Outside OneStock, `?env=qualif&site_id=c00` or the environment entered in the Settings tab is used. The Settings tab opens by itself while no environment is known.

### OneStock calls (`api/`)

Vercel functions call OneStock server side; credentials never reach the browser.

| Function | OneStock route |
|---|---|
| `POST /api/login` | `POST /v3/login` (token stored, renewed on 401) |
| `GET/POST/DELETE /api/suppliers` | `GET /v3/endpoints` with `classification: [{ endpoint_type: [[<supplier type>]] }]`, merged with the suppliers entered in the app (database) |
| `GET /api/items` | `GET /v3/items` (feature `name`) |
| `GET /api/orders` | `GET /v3/orders` with `filter.line_item_group.state.from = <configured statuses>` (2,000 orders max); fields date, sales_channel, types, customer and the line item groups |
| `GET /api/sales-channels` | `GET /v3/sales_channels` (id, name) |
| `POST /api/purchase-orders` | `PATCH /v3/line_item_groups/{id}` for each order line, when a status after launch is set |
| `GET/PUT /api/config`, `GET/PUT/DELETE /api/prices`, `GET/PUT/DELETE /api/strategies`, `GET /api/purchase-orders` | database only |

GET routes are sent as `POST` with `X-HTTP-Method-Override: GET`, as the OneStock API allows.

### Deploying the dynamic version on Vercel

1. Create a Vercel project on this repository (or a second one next to the static version).
2. Storage → add a Postgres database (Neon) to the project: it sets `DATABASE_URL`. Tables are created on first call.
3. Environment variables: `CREDENTIALS_KEY` (long random string, encrypts the stored passwords), optionally `SETTINGS_ADMIN_KEY` (required to change the settings) and `VITE_DATA_MODE=dynamic` (default source). See `.env.example`.
4. Deploy, open the extension, hover the space after *Supplier prices* and click **Settings** (or add `?settings` to the URL), select **Dynamic**, enter the environment connection and the line statuses for each site.

Local run: copy `.env.example` to `.env.local`, then `npm run dev:api` and `npm run dev`.
