# Run and deploy your AI Studio app

This contains everything you need to run your app locally.

View your app in AI Studio: https://ai.studio/apps/e06960ed-7d2c-45bc-be51-1ff696f59058

## Run Locally

**Prerequisites:**  Node.js


1. Install dependencies:
   `npm install`
2. Set the `GEMINI_API_KEY` in [.env.local](.env.local) to your Gemini API key
3. Run the app:
   `npm run dev`

## OneStock design system

The UI follows the OneStock product design system (back-office):

- `styles/onestock.css`: design tokens (colours, spacing, radii, Roboto type scale) and component styles.
- `components/os/`: React versions of the `Os*` components used here (OsIcon, OsButton, OsBadge, OsTag, OsCheckbox, OsSwitch, OsSegmentedControl, OsAlert, OsStepper).
- `components/Layout.tsx`: content area only. The app runs as an extension inside the OneStock back-office, which already provides `OsSideMenu` and `OsNavBar`.
- `public/icons/`: official OneStock icons. Do not substitute another icon set.

## Two versions: static and dynamic

The same code builds two versions, selected by `VITE_DATA_MODE` at build time:

| | Static (default) | Dynamic (`VITE_DATA_MODE=dynamic`) |
|---|---|---|
| Orders, items, suppliers | Sample data (`constants.tsx`) | OneStock API of the calling site |
| Settings and prices | Browser storage | Vercel Postgres database, per environment + site ID |
| Commands | `npm run dev`, `npm run build` | `npm run dev:dynamic` + `npm run dev:api`, `npm run build:dynamic` |

### Tabs

- **Strategies**: wave strategies and the consolidation simulation.
- **Supplier prices**: purchase prices per supplier and item, with quantity tiers (degressive prices), and the franco of each supplier. Entry by hand or Excel import; *Download template* gives an example file (also in `public/templates/supplier-prices-example.xlsx`, regenerated by `npm run template`).
- **Settings** (hidden): shown with `?settings` in the URL, or toggled with Ctrl+Shift+S. OneStock API user and password (a token is requested with `POST /login`), order line statuses to retrieve, and the `endpoint_type` classification of supplier stock points.

### OneStock context (dynamic version)

The extension needs the environment and the site ID of the back-office session that opens it (`services/context.ts`). They are read from the URL (`?env=qualif&site_id=c00`, also `environment` / `siteId`, query or hash), or from a `postMessage` of the host window (`{ env, site_id }`, at the root or under `context`). The extension posts `{ type: 'wave-orchestrator:ready' }` to its parent when it waits for that message. `prod` / `production` targets `https://<site>.api.onestock-retail.com/v3`, any other environment `https://<site>.api.<env>.onestock-retail.com/v3`.

### OneStock calls (`api/`)

Vercel functions call OneStock server side; credentials never reach the browser.

| Function | OneStock route |
|---|---|
| `POST /api/login` | `POST /v3/login` (token stored, renewed on 401) |
| `GET /api/suppliers` | `GET /v3/endpoints` with `classification: [{ endpoint_type: [[<supplier type>]] }]` |
| `GET /api/items` | `GET /v3/items` (feature `name`) |
| `GET /api/orders` | `GET /v3/orders` with `filter.line_item_group.state.from = <configured statuses>` (2,000 orders max) |
| `GET/PUT /api/config`, `GET/PUT/DELETE /api/prices` | database only |

GET routes are sent as `POST` with `X-HTTP-Method-Override: GET`, as the OneStock API allows.

### Deploying the dynamic version on Vercel

1. Create a Vercel project on this repository (or a second one next to the static version).
2. Storage → add a Postgres database (Neon) to the project: it sets `DATABASE_URL`. Tables are created on first call.
3. Environment variables: `VITE_DATA_MODE=dynamic`, `CREDENTIALS_KEY` (long random string, encrypts the stored passwords), optionally `SETTINGS_ADMIN_KEY` (required to change the connection settings). See `.env.example`.
4. Deploy, then open the extension from the OneStock back-office with `?settings` (or Ctrl+Shift+S) to enter the API user and password and the line statuses for each site.

Local run: copy `.env.example` to `.env.local`, then `npm run dev:api` and `npm run dev:dynamic`.
